# Contributing

1. Pick or create a task with a requirement, acceptance criteria, and owner.
2. Branch from updated `main` using `feat/`, `fix/`, `docs/`, `refactor/`, `test/`, or `chore/`.
3. Keep changes scoped; include tests and updates to affected documentation.
4. Run available lint, types, tests, and build checks; record unavailable checks as such.
5. Open a PR using `.github/PULL_REQUEST_TEMPLATE.md` and request independent review.
6. Merge only after required checks/reviews pass. Release requires separate approval.

See `docs/delivery/GIT-BRANCHING.md` and `docs/delivery/DEFINITION-OF-DONE.md`.
